\section{Profile}
I automate the boring path and then put a human at the end of it. The agent opens the pull request;
a person merges it. High-risk changes cannot be approved at all, a rejection has to carry a written
reason that goes back into the next attempt, and every action lands in a log nobody can edit. That
boundary is the whole design. Without it, a wrong edit costs you a main branch instead of a
rejected pull request.
