# Finding and verifying an XML sitemap

An XML sitemap lists the important URLs of a website to help search engines crawl it
efficiently. If you want to locate an existing sitemap for a site, there are several
reliable ways to do it.

## Check common sitemap URLs

Most websites place their sitemap in predictable locations. Try visiting:

```
https://example.com/sitemap.xml
https://example.com/sitemap_index.xml
https://example.com/sitemap/
```

Replace `example.com` with the target domain. Many CMS platforms like WordPress or Wix
automatically generate sitemaps at these paths.

## Inspect robots.txt

Websites often declare their sitemap location in the robots.txt file. Visit:

```
https://example.com/robots.txt
```

Look for a line like:

```
Sitemap: https://example.com/sitemap.xml
```

This is a direct link to the sitemap that search engines use.

## Use Google Search Console (for your own site)

If you own the site:

1. Sign in to Google Search Console.
2. Select your property.
3. Go to **Index → Sitemaps**.
4. View submitted sitemaps or add a new one.

This method also shows when Google last accessed the sitemap and any errors found.

## Search engine queries

You can sometimes find a sitemap by searching Google with:

```
site:example.com filetype:xml
```

This may reveal publicly accessible XML sitemaps indexed by Google.

## Best practices

- Ensure the sitemap is UTF-8 encoded and uses absolute URLs.
- Keep it under 50MB and 50,000 URLs per file; split into multiple files if needed.
- Host it at the site root for maximum coverage.
- Submit it via Search Console or reference it in robots.txt for better discovery.

## How this repo does it

Both files are generated by `scripts/prerender.mjs` on every `npm run build`, so neither
can drift from the routes that actually exist:

| File | Where it comes from |
|---|---|
| `dist/sitemap.xml` | The same route list the prerender walks, so a new project is in the sitemap the moment it is in `portfolio.js`. |
| `dist/robots.txt` | `public/robots.txt` with its `Sitemap:` line rewritten from `site.url`. |

`site.url` in `src/data/portfolio.js` is the only place the domain is written. Change it
there and the sitemap, robots.txt, canonical tags, OG/Twitter URLs and JSON-LD all follow.
Never paste the domain a second time.

The checks above, applied to this site once it is deployed:

```
https://harishgreddy.vercel.app/sitemap.xml     # 15 absolute URLs, UTF-8, at the root
https://harishgreddy.vercel.app/robots.txt      # declares the sitemap
```

There is no `public/sitemap.xml`. A hand-written copy would be a second source of truth
that goes stale the moment a project is added, which is exactly the failure this setup
is built to avoid.
