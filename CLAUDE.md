# Harish G Portfolio: Project Rules

> **Binding.** Where this file and a generic skill or habit disagree, **this file wins.**
> The user's global `~/.claude/CLAUDE.md` code-style rules apply on top of it.

## 1. Golden rules (never violate)

1. **`src/data/portfolio.js` is the only source of content.** Profile text, projects, skills,
   experience, education, all of it. A component that hardcodes a name, a blurb, a metric or a tag
   is wrong, even if it renders correctly.
2. **The resume and `portfolio.js` must not disagree.** Same project names, same numbers, same
   claims. Change one, change the other in the same commit.
3. **Never claim a number you cannot point at.** Every metric on this site traces to a real repo:
   a commit count, a language count, a measured latency. No rounded-up guesses.
4. **`react-router-dom` stays on v6.** v7 breaks the SSR build. Do not upgrade it, and do not let a
   transitive bump drag it forward.

## 2. Architecture

`src/data/` → `src/pages/` → `src/components/`, one direction only.

| Layer | Rule |
|---|---|
| `src/data/portfolio.js` | Plain exported objects. No JSX, no imports from anywhere else in `src/`. |
| `src/pages/*.jsx` | Read from `src/data/`, compose components. **A page never imports another page.** |
| `src/components/*.jsx` | Presentational. Take props; do not reach into `portfolio.js` themselves. |
| `src/components/ui/` | shadcn/ui primitives. Regenerated by the CLI, so do not hand-edit. |
| `src/lib/` | Pure helpers (`utils.js`, `highlight.js`). No React, no data. |

Routes live in `src/App.jsx` and nowhere else.

## 3. Stack (pinned: a swap needs a note in this file)

React 18 · Vite 5 · **react-router-dom 6** · Tailwind CSS 3 + shadcn/ui (Switchboard tokens) ·
framer-motion · lucide-react. Ship no new dependency for what a few lines of the existing stack does.

> **2026-09-12:** Editorial Light → **Switchboard**: Schibsted Grotesk / Atkinson Hyperlegible Next /
> Martian Mono, carmine primary, and a live dark palette (`.dark` on `<html>`, set before paint by
> `index.html` and toggled by `ThemeToggle.jsx`). `scripts/make-og-image.py` mirrors the light tokens as
> RGB tuples, so a palette change means updating and re-running it.

## 4. Styling

- Colours, radii and spacing come from the theme tokens in `src/index.css` / `tailwind.config.js`.
  **A raw hex value in a component is a bug.**
- Use the shadcn primitives in `src/components/ui/` before writing a new one.
- Dark mode and keyboard focus are not optional. Every interactive element stays reachable and
  visible in both themes.
- **Text contrast is AA (4.5:1) in both themes.** An opacity modifier on a text colour is where this
  breaks: `text-muted-foreground/70` measured 3.12:1 on light and 4.13:1 on dark and failed both.
  Use the bare token; if a thing is decorative, mark it `aria-hidden` rather than fading it.
- **The three families are self-hosted from `public/fonts`,** not fetched from Google. Loading them
  from fonts.googleapis.com cost a render-blocking request to a third origin plus a second connection
  to fonts.gstatic.com before any text could paint: 960ms of the mobile LCP. `src/index.css` holds the
  `@font-face` block and the URL to regenerate them from. The filenames are *not* content-hashed and
  `vercel.json` caches them for a year as immutable, so a regenerated face needs a **new filename**.

## 5. Build & SSG

`npm run build` = `vite build` → `vite build --ssr` → `node scripts/prerender.mjs`.

- The prerender derives its route list from `projects` in `portfolio.js`. **A new project needs no
  build change**; a new *page type* needs a route in `App.jsx` and a branch in `metaFor()`.
- `scripts/prerender.mjs` also writes `sitemap.xml`, `robots.txt` and `404.html` into `dist/`. There
  is no `public/sitemap.xml`; the generated one is the only one, so it can never go stale.
- **`site.url` in `portfolio.js` is the only place the domain is written.** Canonical tags, OG/Twitter
  URLs, JSON-LD, every `<loc>` in the sitemap and the `Sitemap:` line in robots.txt are all derived
  from it. Never paste the domain a second time. No trailing slash. The one exception is the static
  fallback copy in `index.html`, which the prerender overwrites per route.
- `public/og-image.png` is generated by `python scripts/make-og-image.py`, never hand-edited.
  It is the one place the domain is baked in as pixels rather than read from `site.url`, so
  **changing `site.url` means re-running that script** or the share card advertises the old
  address. It reads `public/profile.jpg` and the light-theme tokens from `src/index.css`.
- **`vercel.json` is the host contract, and JSON cannot hold a Why/What header, so it is documented
  here.** `trailingSlash: false` makes Vercel redirect `/works/zentrax/` to `/works/zentrax`; without
  it the host answered 200 at *both*, so every page existed at two URLs and split its own ranking
  signals. The `headers` entries give the content-hashed `/assets` and the self-hosted `/fonts` a
  one-year immutable cache, in place of the 4-hour default that applied to everything.
- `public/google*.html` is the Google Search Console ownership token. It looks like a stray
  hash-named file; it is not. Deleting it un-verifies the property. Same for any future
  `BingSiteAuth.xml`.
- A malformed project object fails the build here rather than at runtime. That is the intended gate;
  do not add try/catch to make the prerender survive bad data.
- **Verify SSG on a static host, never `vite preview`.** Its SPA fallback serves `index.html` for any
  path, so a broken prerender still looks fine and hydration errors appear out of nowhere in prod.

## 6. Resume

- **`public/resume.tex` is the source. `public/resume.pdf` is generated. Never hand-edit the PDF.**
  Rebuild: `pdflatex -interaction=nonstopmode -output-directory=public public/resume.tex` (twice),
  then delete the `.aux` / `.log` / `.out` it leaves behind.
- `public/resume-anz-ai-engineer.tex` is a role-targeted variant. It drifts from `resume.tex` on
  purpose, so do not "sync" the two. The same applies to the other company-targeted variants
  (`resume-anz-platform-engineer`, `resume-cgi-*`, `resume-hpe-*`).
- **The `resume-<role>.tex` family is generated, not hand-written.** `resume-agentic-ai`,
  `resume-java-developer`, `resume-mobile-developer`, `resume-fullstack-developer`,
  `resume-ml-engineer`, `resume-backend-platform`, `resume-python-developer` and
  `resume-automation-rpa` all come from the `resume-forge` skill
  (`~/.claude/skills/resume-forge/`). Regenerate or re-score one with that skill rather than
  editing it ad hoc, so the family keeps one template and one set of numbers.
- **These variants draw on a wider evidence ledger than `portfolio.js`.** The ledger
  (`docs/resume-evidence.json`, rebuilt by the skill) merges `portfolio.js` with the project blocks
  of the shipped `.tex` variants, which carry real work the site does not list — Lendly, AI Personal
  CFO and Talo, the Dental Clinic AI Assistant, the forecasting systems. §1.2 still binds everything
  the *site* shows; a variant may go beyond it, but may never contradict it, and every number must
  still trace to something real (§1.3). The skill's evaluator enforces exactly that.
- One page. If something new goes on, something old comes off.
- `dist/` is gitignored build output. Editing a `.tex` under `dist/` changes nothing.

## 7. Coding standards

- Every file opens with the **Why / What / Result / Changelog** header comment (see `portfolio.js`,
  `prerender.mjs`, this file). Every non-trivial function gets a doc comment covering its inputs,
  its output and why it exists.
- Comments explain **why**, not what. A comment restating the line above it is deleted.
- Components stay small and readable over clever. No abstraction with one caller.
- Never render user-supplied or data-file HTML with `dangerouslySetInnerHTML`. `highlight.js`
  deliberately emits React spans instead.

## 8. Git & workflow

- One change per branch, one concern per commit. Conventional Commits: `feat(works): …`,
  `fix(prerender): …`, `docs: …`.
- The commit message says **why**, not just what changed.
- Content change and its resume counterpart land together (§1.2).
- Never commit `node_modules/`, `dist/`, `dist-ssr/`, or LaTeX build droppings.

## 9. Definition of Done

1. `npm run build` completes clean.
2. `dist/works/<slug>/index.html` contains real rendered content, not an empty `<div id="root">`.
3. The page renders correctly at `npm run dev` in both themes, keyboard-navigable.
4. `resume.tex` rebuilt and still one page, if the change touched resume content.
5. Nothing hardcoded that belongs in `portfolio.js`.
